# Протокол: аудит, доказательство, правка

## Режимы

**Аудит (по умолчанию).** Read-only. Ничего не меняется в репозитории, кроме самого отчёта,
если его просят сохранить файлом. Это режим для любой фразы без явного «почисти»/«поправь»:
«доки протухли», «посмотри на доки», «аудит документации».

**Правка.** Только после отчёта и явного «давай»/«почисти»/конкретного класса («поправь
протухшее»). Один класс — одна правка/PR, как в `runway` и всём остальном наборе: находка
класса 3 (задвоенное) не тянет за собой заодно переписанный стиль класса 5 (раздутое), даже
если оба в одном файле.

Не угадывай режим по интонации. «Доки разрослись, с этим пора что-то делать» — всё ещё аудит;
правка начинается с явного слова о правке.

## Доказательство, а не ощущение

Каждая находка класса 1 (протухшее) и 2 (брошенное) требует **факта**, не вкуса:

- для протухшего: цитата из документа + текущее состояние кода/команды + как проверено (команда
  запущена, путь проверен `rg`/`ls`, дата последнего релевантного коммита);
- для брошенного: `git log` на предмет коммита удаления, либо явное отсутствие в дереве;
- для задвоенного: обе цитаты рядом, видно ли фактическое расхождение сейчас или только риск
  будущего расхождения — это разные по срочности находки, не путай их в отчёте.

«Кажется устаревшим» без проверки — не находка, а гипотеза; если не успел проверить, так и
пиши в отчёте, не выдавай за находку.

## Suggest-first, не тихая перезапись

Даже в режиме правки — для документов не из «безопасного» списка ниже правка идёт как
предложение (diff или новый текст целиком) с коротким «почему», и применяется после «да», если
запрос изначально не был однозначным пакетным «почисти всё». Безопасный список — документы,
по которым расхождение невозможно трактовать двояко (мёртвая ссылка, путь к несуществующему
файлу, дата в прошлом): их чинить без отдельного подтверждения на каждую можно сразу внутри
уже подтверждённой правки класса.

## Защищённые документы — не трогать даже в режиме правки

- Файлы, которые генерирует другой инструмент (автосгенерированный CHANGELOG, API-референс из
  кода) — находка идёт в «недостающее»/«протухшее» с указанием, что поправить нужно источник
  генерации, не файл.
- Лицензии, файлы со внешним обязательным форматом (SECURITY.md под шаблон площадки).
- Документы, у которых в начале явно стоит «не редактировать руками» или подобное — уважай
  пометку, даже если она сама выглядит старой; подними вопрос отдельно.

## Что не находка

- Осознанная краткость со ссылкой «подробности — там-то» (см. SKILL.md «Границы»).
- Чужое решение не документировать что-то явно — комментарий или запись в `decisions/` с
  причиной рядом: это решение, а не брошенное/недостающее. См. `honesty.md` правило 1 из
  `runway`, применённое к документации, а не к коду.
- Стилистические предпочтения без цены для читателя («я бы написал иначе») — не находка,
  не трогай, пока не спросят явно про стиль.
